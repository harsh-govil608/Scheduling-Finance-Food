# Document 02: Design Language

## Document Name
Design Language

## Purpose
Define the overarching visual identity system — the unifying logic that ties typography, color, iconography, motion, spacing, and illustration into a single coherent language — so that every subsequent Design Foundations document (Typography, Color System, Icons, Illustrations, and later Motion and Spacing documents) is a specialization of one shared system rather than an independently invented one.

## Why It Exists
A design system built document-by-document, with no parent framework, tends to drift: typography gets decided in isolation from color, icons get commissioned without reference to the illustration style, and the result reads as a kit of parts rather than a "language." Because the product must feel like ONE assistant across Productivity, Finance, and Health, and because Phase 7 explicitly separates visual/verbal design language from Phase 2's behavioral tone documents, this document exists as the connective layer: it states the identity the whole system is expressing, defines the shared vocabulary (terms, tokens, naming conventions) every other Foundations document must reuse, and prevents each visual discipline from being designed as a silo.

## Approximate Page Count
8-10 pages

## Sections
1. **Design Language Overview & Intent** — the identity the system is meant to project (e.g., calm authority, quiet competence) and how it expresses the Design Principles (Phase 7 Doc 01) visually.
2. **Relationship to Brand Identity** — how this design language sits under/alongside the company's brand identity (logo, brand voice) established in earlier phases, and where the boundary lies.
3. **System Architecture & Token Model** — the shared token/naming framework (e.g., primitive vs. semantic tokens) that Typography, Color, Icons, Illustrations, Motion, and Spacing documents must all conform to.
4. **Cross-Discipline Coherence Rules** — explicit rules for how typography, color, icons, and illustration must relate to one another (e.g., icon stroke weight matched to type weight) so the system reads as one language.
5. **Pillar Differentiation Within One Language** — the framework for how Productivity, Finance, and Health can be visually distinguishable (e.g., through accent, not through separate systems) while remaining unmistakably one assistant.
6. **Platform & Context Adaptability** — how the design language flexes across mobile, web, wearable, and voice/glanceable surfaces without fragmenting into separate languages.
7. **Light & Dark Mode / Environmental Adaptation** — requirements for the language to hold together across appearance modes and accessibility settings (e.g., high contrast, reduced motion).
8. **Governance & Extension Process** — how new components, patterns, or tokens get proposed, reviewed, and folded into the design language over time.
9. **Anti-Patterns** — named examples of what would violate the design language (e.g., a pillar team introducing its own type scale) and why.
10. **Glossary of Shared Terms** — canonical definitions for terms used across all downstream Foundations documents.

## Deliverables
- A definition of the design language's core identity and intent, tied explicitly to the Design Principles.
- A token/naming architecture that Typography, Color System, Icons, Illustrations, and future Motion/Spacing/Elevation documents must inherit.
- Cross-discipline coherence rules and named anti-patterns.
- A governance process for proposing and approving extensions to the language.

## Dependencies
Requires Design Principles (Phase 7 Doc 01); informed by Phase 1 Company Foundation brand identity documents and Phase 2 Doc 02 Product Philosophy Document; is a direct prerequisite for Typography (Phase 7 Doc 03), Color System (Phase 7 Doc 04), Icons (Phase 7 Doc 05), and Illustrations (Phase 7 Doc 06).

## Teams
Design, Brand, Product, Engineering

- [ ] Anti-pattern list reviewed with all three pillar design leads (Productivity, Finance, Health).
- [ ] Signed off by: Head of Design (required), Brand Lead (required), VP Engineering (consulted).
